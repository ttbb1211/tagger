# 中文数据源默认启用

## 背景

四个实验性来源（网易云、酷狗、酷我、LrcApi）的 `Descriptor.Enabled` 自接入起一直是 `false`，只有 MusicBrainz / LRCLIB / Apple 默认开启。结果是**全新的数据目录**（首次运行、换机器、换 `-data-dir`）里中文源默认是关闭的，用户要自己进「设置 → 数据源」逐个打开。

实测踩到的场景：同一个 exe 在已有数据目录里跑，中文源是勾选的；换到一个空目录（新的 `./data`）再跑，中文源全部未勾选。原因是开关状态由 `provider_settings` 表持久化，空目录没有历史记录，就回落到代码默认值。

## 实现

把四个实验性来源的代码默认值改为开启：

| 文件 | 改动 |
| --- | --- |
| `internal/providers/netease/client.go` | `Enabled: false` → `true`，`QuotaLabel` 改为「实验性网页接口 · 默认启用」 |
| `internal/providers/kugou/client.go` | 同上 |
| `internal/providers/kuwo/client.go` | 同上（原为「实验性网页接口 · 默认关闭」） |
| `internal/providers/lrcapi/client.go` | `Enabled: false` → `true` |
| `frontend/src/mock/data.ts` | 四个 mock provider 的 `enabled`/`health`/`quotaLabel` 对齐真实后端 |
| `frontend/src/mock/data.test.ts` | 原断言 `kuwo.enabled === false` 改为「四个来源均 `experimental && enabled`」 |

`Health` 保持 `HealthDegraded`，`Experimental` 保持 `true`——只是默认开关变了，实验性标记和「可能随时失效」的提示不变。

## 为什么升级不会覆盖用户的选择

`Registry.descriptor()` 的逻辑是：

```go
enabled, overridden := r.enabled[id]
if overridden {
    descriptor.Enabled = enabled   // 只有存在持久化记录时才覆盖代码默认值
}
```

`r.enabled` 来自 `provider_settings` 表。**没有记录才用代码默认值**，因此：

- 已经手动关闭过某个来源的用户，升级后仍然是关闭的（持久化记录生效）；
- 只在全新数据目录里才会看到新的默认值。

这一条与 [78-v1.0.5发布说明](78-v1.0.5发布说明.md) 里「升级不会替用户打开已关闭的来源」的承诺一致。

## 验证

- `go test ./...` 全绿。`internal/providers/registry_test.go` 中 `netease` 的用例用的是 `NewPlaceholder` 合成描述符，与真实 provider 无关，不受影响。
- `npm test` 全绿；`npx tsc --noEmit` 通过。
- 手工核对：删掉 `data/` 后用新 exe 启动，设置页四个中文源默认勾选；把某个源关掉再重启，仍是关闭。
