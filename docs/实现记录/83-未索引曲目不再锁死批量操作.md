# 未索引曲目不再锁死批量操作

## 背景

老板在 `D:\#Pop单曲`（182 首）上实测到两个现象：

1. 勾选曲目后，底部黑色选择条出现，但三个按钮（批量编辑 / 整理文件 / 抓取元数据）全是灰的，点不动；
2. 顶部「批量补全」也是灰的。

排查后确认**不是浮层挡住点击**，而是按钮被 `disabled` 了。根因是一个文件：

```
#Pop单曲  共 182 首
  indexed  181
  error      1   ← 欢子-愚爱.wav  present=1 writable=1
parse_error: read tags: call "call \"taglib_file_tags\": __cxa_allocate_exception
             (recovered by wazero)"
```

`internal/scanner/scanner.go` 在读这个 WAV 的标签时 taglib/wazero 抛异常，把该曲目的
`sync_state` 落成 `error`。而前端 `isTrackIndexed()` 把 `error` 和 `draft`（正在索引）
一视同仁地判为「未索引」，于是两条禁用链同时成立：

| 症状 | 禁用条件 | 判定输入 |
| --- | --- | --- |
| 顶部「批量补全」置灰 | `pageTotal === 0 \|\| hasVisibleUnindexed` | 列表里任意一首未索引 |
| 选择条三个按钮全灰 | `hasUnindexedSelection` | 选择里任意一首未索引 |

后端也拦：`handleMatchBatch` 只要请求里含未索引曲目就整批返回
**409 `track_not_indexed`**。

所以这是**单点文件永久锁死整个目录**：那个 WAV 不修好，`#Pop单曲` 的批量补全就永远是灰的，
界面上没有任何出路。

## 实现

思路：把「未索引」从**一票否决**改成**按可操作子集执行 + 明确告知跳过**。

### 前端 `LibraryPage.tsx`

新增两个纯函数：

- `splitUnindexedTracks(tracks)` → `{actionable, skipped}`；
- `skippedTracksLabel(skipped)` → `two.flac（解析失败）` 这样的明细串（超过 3 首截断成「等 N 首」）。

改动点：

- 顶部「批量补全」（内联按钮与「操作」弹层各一处）禁用条件收窄为 `pageTotal === 0`。
- 选择条三个按钮的禁用条件从 `hasUnindexedSelection` 改为**各自的可用子集为空**：
  - 批量编辑 → `actionableSelection.length === 0`
  - 整理文件 → `organizableTracks.length === 0`
  - 抓取元数据 → `actionableSelection.length === 0`
  并在 `title` 里写出实际作用数量。
- `openReviewSelection()` 解析出曲目后先 `splitUnindexedTracks`：
  - 可操作集合为空 → 提示「当前筛选的 N 首曲目都未完成索引，暂时无法批量补全」，不建任务；
  - 否则只用可操作曲目建任务，并把 `skipped` 带进确认框。
- `reviewConfirmDescription(count, pending, skipped)` 增加一段：
  > 已跳过 1 首未完成索引的曲目：two.flac（解析失败）。这些曲目需要先完成索引（解析失败的可在曲目列表点状态图标重新解析）。
- `applyBatchEdit` 不再因为「含未索引」直接报错返回，改为按 `writable && isTrackIndexed` 过滤；
  过滤后为空才提示。
- 选择条新增「已跳过 N 首未索引曲目」提示（`.selection-skip`），`title` 里列出文件名与原因。
- 新增 `retryTrackParse(track)`：调 `rescanTrack` 重新解析单曲，并把结果如实回报
  （仍失败时提示检查文件是否损坏）。

### 前端 `TrackList.tsx`

- 状态列对 `syncState === 'error'` 从「不可点的 `<span>`」改为可点的重试按钮
  （`aria-label="重新解析 <标题>"`，无 handler 时 `disabled`）。之前只有一个红图标，
  用户既不知道原因也没有自救入口。
- 新增 `bottomSpacer` 属性：选中时在 Virtuoso 的 `Footer` 里插入等高占位，避免底部
  选择条盖住列表最后 1~2 行。

### 后端 `server.go`

`handleMatchBatch` 从「含未索引曲目整批 409」改为**跳过**：

```go
indexed := make(map[string]struct{}, len(tracks))
for _, track := range tracks {
    if track.SyncState == "" || track.SyncState == domain.SyncIndexed {
        indexed[track.ID] = struct{}{}
    }
}
if len(indexed) == 0 {
    s.writeError(c, consts.StatusConflict, "track_not_indexed", "所选曲目都未完成索引，暂时无法抓取元数据")
    return
}
eligible := ... // 保留请求顺序，只留 indexed 里的
request.TrackIDs = eligible
```

全部不可用时仍然 409，避免静默创建一个 0 曲目任务。前端已经过滤过，这里是兜底 ——
防止 CLI、旧前端或其它入口再撞同一堵墙。

## 验证

- 后端（云服务器 `/home/builder/src`，builder 用户）：
  `go vet ./...` OK、`GOOS=windows GOARCH=amd64 go vet ./cmd/tagger/` OK、
  `go test ./...` 全绿。
  新增 `TestBatchMatchSkipsUnindexedTracks`（`internal/server/server_test.go`）：
  用 reconcile 造一个停在 `draft` 的曲目，与一个正常曲目一起提交 →
  202 且任务 `total == 1`、payload 里只有正常曲目；只提交未索引曲目 → 409 `track_not_indexed`。
- 前端：`tsc --noEmit` 通过。
  `LibraryPage.test.tsx` 新增两条：
  - 列表里有解析失败的曲目时「批量补全」仍可点，确认框写出「已跳过 1 首…（解析失败）」；
  - 全选（含未索引）后选择条按钮仍可点，出现「已跳过 1 首未索引曲目」，确认后只把可操作曲目交给审核页。
  新增 `TrackList.test.tsx`：重试按钮只出现在 `error` 曲目上、无 handler 时禁用、`bottomSpacer` 生效。
  （jsdom 没有布局，react-virtuoso 不渲染行，所以该文件用一个「全量渲染 data」的替身。）
